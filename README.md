# 手写 GPT 项目说明

一个从零手写的简化版 GPT 语言模型（中文对话机器人），适合初学者理解 GPT 的核心原理：
**给定前面所有的字，预测下一个字（自回归语言模型）**。

---

## 一、项目简介

这个项目不依赖任何大模型库，只用 PyTorch 从零搭建了一个精简版的 GPT：

- 用一段段"问答式"对话文本训练；
- 训练后，你输入一句话，模型会逐字续写，直到写出结束符 `<sep>`；
- 续写出来的内容就是模型的"回答"。

整个模型结构 = **词嵌入 + 位置嵌入 + 6 层 Transformer Decoder + 输出映射**。

## 五、数据格式说明

### data/train.txt（训练语料）

- 每**两段对话之间用一个空行**分隔；
- 一段对话里，**每一行是一句话**（一问或一答）。

```
今天好点了吗？
一天比一天严重
吃药不管用，去打一针。别拖着

是的。下辈子想做只萤火虫
可是萤火虫太容易被抓了还是改一个吧
```

### data/vocab.txt（词表）

每行一个字/符号，`索引 = 行号`。**前 3 行是特殊符号，含义固定**：

| 索引 | 符号   | 含义                                       |
| ---- | ------ | ------------------------------------------ |
| 0    | `<pad>`| 填充符：补齐长度用，不参与计算损失         |
| 1    | `<unk>`| 未知符：词表里没有的字都映射成它           |
| 2    | `<sep>`| 分隔符：标记"一句话结束 / 回答结束"        |

## 六、代码逻辑详解

### 6.1 核心思想：预测下一个字

GPT 的训练方式是**自回归**：给模型「前 n 个字」，让它预测「第 n+1 个字」。

对一段对话，代码会做如下处理（`MyDataSet.__getitem__`）：

```
原文(每句话后加<sep>)：你 好 <sep> 谢 谢 <sep>
输入(去掉最后一个)  ：你 好 <sep> 谢 谢
输出(右移一位)      ：好 <sep> 谢 谢 <sep>
```

模型看到「你 好 <sep> 谢 谢」，就要预测「好 <sep> 谢 谢 <sep>」。
这样每个位置都在学"看到前面的字 → 猜下一个字"。

### 6.2 整体流程图

```mermaid
flowchart TD
    A[对话文本 train.txt] --> B[分词: 每个字→词表id, 句间加&lt;sep&gt;]
    B --> C[构造输入/输出对: 输入去尾, 输出去头]
    C --> D[padding补齐到等长]
    D --> E[嵌入层: 词向量+位置向量]
    E --> F[6层 Decoder<br/>自注意力(带mask)+前馈网络]
    F --> G[输出映射层: 每个位置→词表上每个字的得分]
    G --> H{训练 or 推理}
    H -- 训练 --> I[交叉熵损失 → 反向传播 → Adam更新参数]
    H -- 推理 --> J[贪心/随机解码: 逐字续写直到&lt;sep&gt;]
    J --> K[取最后一个&lt;sep&gt;之间的内容 = 回答]
```

### 6.3 两个 Mask 的作用

Transformer 中，每个字都要"看"序列里所有字（注意力），但不是所有位置都能看：

| Mask | 作用 | 实现 |
| ---- | ---- | ---- |
| **padding mask** | 遮住填充的 `<pad>`，因为空位没有真实含义 | `seq_k == 0` 的位置设为掩码 |
| **lookahead mask**（因果 mask） | 遮住"未来的字"。预测第 n 个字时只能看前 n-1 个，否则等于作弊 | 上三角矩阵 `np.triu(..., k=1)` |

两个 mask 相加后，任一位置为真就会被遮住（`torch.gt(x, 0)`）。

### 6.4 模型组件（自底向上）

| 组件 | 作用 |
| ---- | ---- |
| `EmbeddingLayer` | 词嵌入（字→向量）+ 位置嵌入（位置→向量），两者相加 |
| `MultiHeadAttention` | 核心。每个字通过 Q/K/V 计算与其他字的相似度（注意力权重），加权融合信息 |
| `FeedForward` | 每个字独立做的两层全连接 + ReLU，做"深度加工" |
| `DecoderBlock` / `DecoderLayer` | 一层 = 注意力 + 前馈，均带残差连接和层归一化 |
| `Decoder` | 嵌入层 + 多层堆叠，并计算合并后的 mask |
| `GPT_Model` / `GPT` | Decoder + 输出映射层（隐藏向量→词表得分）+ 损失函数 |

### 6.5 两种生成方式（对话回答）

| 方式 | 说明 | 特点 |
| ---- | ---- | ---- |
| `greedy_decoder` | 每步选概率最大的字 | 稳定，但回答可能单调 |
| `random_decoder` | 按概率随机采样（top_n 候选） | 回答更多样，可能不稳定 |

`answer()` 会解析模型续写的内容：取**倒数第二个 `<sep>`**（提问结束）到**最后一个 `<sep>`**（回答结束）之间的字，作为回答返回。

### 6.6 训练流程（手写gpt.py 主程序）

1. 读取训练数据（默认只取 30 段对话，方便快速跑通）；
2. 读取词表，建立 `字 → id` 映射；
3. 设置超参数（见下表）并创建模型、Adam 优化器；
4. 训练 `epochs` 轮：前向 → 算损失 → 反向传播 → 梯度裁剪 → 更新参数；
5. 训练结束进入对话模式。

### 6.7 超参数说明

| 参数 | 值 | 含义 |
| ---- | --- | ---- |
| `max_pos` | 300 | 支持的最大序列长度 |
| `d_model` | 768 | 每个字的向量维度 |
| `d_ff` | 2048 | 前馈层中间维度 |
| `d_k, d_v` | 64 | 每个注意力头的维度 |
| `n_layers` | 6 | Decoder 层数 |
| `n_heads` | 8 | 注意力头数 |
| `lr` | 1e-4 | 学习率 |
| `batch_size` | 1 | 每批 1 段对话 |
| `epochs` | 10 | 训练轮数 |

## 七、两个脚本的区别与联系

| | 手写gpt.py | predict.py |
| --- | --- | --- |
| 职责 | 训练 + 对话 | 仅对话（推理） |
| 是否重新训练 | 是 | 否，加载 `model.pt` |
| Decoder 层写法 | 教学演示版：每层 2 个注意力块（`DecoderBlock`） | 标准版：每层 1 个注意力块（`DecoderLayer`） |
| 词表/超参数加载 | 有 | 有（原代码缺失，已修复） |

> ⚠️ **重要提示**：已通过读取 `model.pt` 权重名称确认，`model.pt` 的层内结构是
> `dec_self_attn` + `pos_ffn`（即标准单注意力版），与 **predict.py 完全一致**，可直接加载。
> 而 `手写gpt.py` 用的是双注意力版（`attention_block1/attention_block2`），
> 结构命名不同，**不能**直接加载 `model.pt`（它自己训练自己的模型，无需加载）。
> 如果你想用 `手写gpt.py` 训练后保存权重给 `predict.py` 用，需先让两者层内结构保持一致。

## 八、常见问题（FAQ）

1. **运行报错 `FileNotFoundError: data/train.txt`**
   请确认在项目根目录（`手写gpt备课/`）下运行命令；代码已统一使用正斜杠路径，兼容 Windows / macOS / Linux。

2. **predict.py 报错 `NameError: word2id` / `NameError: d_model`**
   原代码漏掉了**词表加载**和**模型超参数定义**两处，本项目已修复：
   主程序中补上了加载 `data/vocab.txt`，并补充了与 `model.pt` 维度一致的超参数
   （`d_model=768`、`d_ff=2048`、`n_layers=6`、`n_heads=8` 等）。

3. **训练很慢 / 回答很怪**
   本代码默认只取 30 段对话训练，属于"最小可运行"配置，效果有限。想提升效果：
   - 把 `read_data("data/train.txt", 30)` 的 `30` 删掉，用全部数据；
   - 增大 `epochs`；
   - 生成回答时把 `greedy_decoder` 换成 `random_decoder`（随机采样）。

4. **没有 GPU 能跑吗？**
   能。代码自动检测设备，无 GPU 时用 CPU 训练，只是慢一些。
