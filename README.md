## 一、项目简介

GPT 的本质只有一句话：**给定前文所有字，预测下一个字**。

这个项目做的事情：

1. 读取 `data/train.txt` 中的中文闲聊对话（一问一答，百万行级语料）；
2. 把每段对话转成"字 id"序列，构造"输入右移一位 = 输出"的训练样本；
3. 搭建一个字符级的 Transformer Decoder（词嵌入 + 位置嵌入 + 6 层注意力块 + 前馈层）；
4. 训练它学会"预测下一个字"（交叉熵损失 + Adam 优化器）；
5. 训练完进入终端对话模式：你输入一句话，模型一个字一个字地**续写**出回答，直到写出结束符 `<sep>`。

一句话总结：**模型不会直接"回答问题"，它只是把你的话当作一段对话的前半部分，然后凭训练经验续写出后半部分。**

## 四、如何跑通项目

### 方式一：训练 + 对话（推荐第一次使用）

```bash
cd gpt                       # 进入项目根目录（必须在这里运行，因为代码用相对路径读 data/）
python 手写gpt.py
```

运行过程：

1. 读取 `data/train.txt` 的前 **30 段**对话（默认值，为了快速跑通）；
2. 训练 **10 轮**，屏幕上会显示进度条和每轮的 `Train Loss`（损失越小，学得越好）；
3. 训练结束出现提示 `请输入:`，此时输入一句话并回车，模型就会给出回答；

```
请输入:你好
GPT_Model: ...
请输入:今天天气怎么样
GPT_Model: ...
```

> 按 `Ctrl + C` 退出对话。
> 想用**全部语料**训练：把 `手写gpt.py` 末尾的 `read_data("data/train.txt", 30)` 中的 `30` 去掉即可（训练时间会很长）。

### 方式二：只对话（需要已有 model.pt）

```bash
python predict.py
```

> ⚠️ 前提：当前目录下存在 `model.pt`（训练时保存的权重文件）。仓库本身不含 `.pt` 文件。
> ⚠️ 注意：`predict.py` 的模型结构是"单注意力版"，与 `手写gpt.py` 的"双注意力版"**互不通用**，详见[第九节常见坑](#九两个文件的关系与常见坑)。

## 五、数据文件说明

### train.txt（训练语料）

- **段与段之间用一个空行分隔**，一段就是一次完整对话；
- 段内**每一行是一句话**（轮流发言，一问一答）。

```text
谢谢你所做的一切
你开心就好
开心
嗯因为你的心里只有学习

你们宿舍都是这么厉害的人吗
眼睛特别搞笑这土也不好捏但就是觉得挺可爱
特别可爱啊

（……更多对话，段与段之间空行分隔……）
```

### vocab.txt（词表）

每行一个"字"，行号就是它的 id。**字符级模型**：一个字 = 一个 token。

| id | 符号 | 含义 | 用途 |
|---|---|---|---|
| 0 | `<pad>` | 填充符 | 把短句子补齐到同一长度；训练时被 mask 掉、不计算损失 |
| 1 | `<unk>` | 未知字符 | 词表里没有的字统一用它表示 |
| 2 | `<sep>` | 分隔符 | 标记"一句话结束 / 整段对话结束"，模型靠它知道何时停止说话 |
| 3+ | 汉字/字符 | 正文用字 | 如"堵 人 滚 呐 哇 ， 秒 …" |

> 词表在两个脚本里都是按"字 → id"双向查询：`word_2_index`（字转 id）和 `index_2_word`/`id2word`（id 转字）。

## 六、核心概念（小白必读）

### 1. 字符级语言模型

模型不认识"词"，它眼里只有一个个**字**。每个字先通过"词嵌入表"变成一个 768 维的向量，模型所有计算都在这些向量上进行。

### 2. 自回归：预测下一个字 = 整体右移一位

训练时，把一段对话转成 id 序列后，**输入和标签只差一个"右移"**：

```text
对话 "你好" 转成 id（含 <sep>）：[10, 20, 2, 2]

decoder_input  = [10, 20, 2]     ← 去掉最后一个
decoder_output = [20,  2, 2]     ← 去掉第一个（右移一位）

含义：看到 [10]        应预测 20    （"你"的下一个字是"好"）
      看到 [10, 20]    应预测 2     （"你好"说完了）
      看到 [10, 20, 2] 应预测 2     （整段对话结束）
```

一次前向传播，**每个位置都在同时学"预测下一个字"**，一起算损失、一起更新参数。这就是"教师强制"训练法，非常高效。

### 3. Transformer Decoder 的组成

```text
输入 id 序列 [batch, len]
   │
   ▼
EmbeddingLayer（词嵌入 + 位置嵌入）──────> [batch, len, 768]
   │
   ▼
DecoderBlock × 6 层，每层内部：
   ├─ 自注意力（字与字之间交换信息）
   ├─ 前馈网络 768 → 2048 → 768（每个字独立深加工）
   └─（每一步都带"残差连接 + LayerNorm"稳定训练）
   │
   ▼
Linear(768 → 7548) ──────> [batch, len, 7548] 每个位置对每个字的得分
   │
   ├─ 训练时：与 decoder_output 比对 → 交叉熵损失 → 反向传播
   └─ 推理时：取"最后一个位置"得分最高的字 → 作为下一个字，循环生成
```

### 4. 两种 Mask（掩码）

Mask 的作用是**遮住不该看的位置**。两个脚本里都有这两个函数：

| Mask | 作用 | 直观例子 |
|---|---|---|
| **padding mask** | 遮住 `<pad>` 填充位（没有真实含义） | `seq_k=[5,8,0,0]` → 第 3、4 列全被遮住 |
| **因果/上三角 mask** | 遮住"未来"，防止偷看后面还没生成的字 | 长度 3 的序列 → `[[0,1,1],[0,0,1],[0,0,0]]`，1 的位置被遮 |

两个 mask 相加后大于 0 的位置就是最终要遮住的位置。

### 5. 多头注意力（MultiHeadAttention）

一句话理解：**每个字都去"看"一遍序列里所有的字，决定自己表达时重点参考谁**。
"多头" = 同时用 8 组不同的"看法"（8 个头 × 64 维 = 768 维，正好拼回原维度）。

计算步骤：输入 → 线性变换出 Q/K/V → Q 与 K 做内积算相似度 → softmax 变成权重 → 对 V 加权求和 → 拼回 768 维 → 残差 + LayerNorm。

### 6. 训练 vs 推理

| 阶段 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 训练 | 整句话一次性输入 | 每个位置对下一个字的预测 | 和标签比对算损失，反向传播 |
| 推理（生成） | 当前已生成的句子 | **只取最后位置**的预测作为新字 | 把新字接到句尾，循环往复，直到 `<sep>` |

## 七、代码逻辑详解：手写gpt.py

建议按下面的顺序阅读代码（也是代码从上到下的顺序）。

### 7.1 数据处理部分

| 组件 | 关键函数/方法 | 作用 |
|---|---|---|
| `read_data(path, num)` | — | 读 `train.txt`，按空行切成一段段对话；`num=30` 表示只取前 30 段快速训练 |
| `MyDataSet` | `__getitem__` | 取一段对话 → 按行切 → 每行每个字转 id（查不到用 `<unk>=1`）→ 每行末尾加 `<sep>=2` → 整段末尾再加一个 `<sep>` → 构造"输入=去尾、输出=右移一位"的样本对 |
| | `padding_batch` | DataLoader 的 `collate_fn`：一批样本长度不齐时，用 `<pad>=0` 补齐成规则的 `[batch, max_len]` 矩阵才能并行计算 |

**示例**：对话"你好"转成 id 是 `[10, 20, 2, 2]`，则样本为 `输入=[10,20,2]`，`标签=[20,2,2]`。

### 7.2 两个 Mask 工具函数

| 函数 | 作用 | 返回形状 |
|---|---|---|
| `make_pad_mask(seq_q, seq_k)` | 找出 `seq_k` 中等于 0（`<pad>`）的位置 | `[batch, len_q, len_k]`，`<pad>` 列为 True |
| `make_lookahead_mask(seq)` | 用 `np.triu` 生成上三角矩阵，遮住"未来" | `[batch, len, len]`，上三角为 1 |

### 7.3 模型组件（从零件到整体）

按"从小到大"的组装关系：

```text
MultiHeadAttention（注意力零件）
FeedForward（前馈零件）
        │ 组合成
        ▼
DecoderBlock（一层 Decoder）= 注意力×2 + 前馈×1
        │ 堆叠 6 层
        ▼
Decoder = EmbeddingLayer（词嵌入+位置嵌入）+ 6 × DecoderBlock
        │
        ▼
GPT_Model = Decoder + Linear(768→词表) + CrossEntropyLoss
```

各组件要点：

- **`EmbeddingLayer`**：每个字的最终表示 = 词向量 + 位置向量。没有位置嵌入，模型就分不清"我爱你"和"你爱我"。
- **`MultiHeadAttention`**：Q/K/V 三个线性投影 → 拆 8 个头 → 内积 + softmax 得注意力权重 → 加权求和 → 拼回 → 残差 + LayerNorm。被 mask 的位置填 `-1e9`，softmax 后概率趋近 0（等于"看不见"）。
- **`FeedForward`**：`768 → 2048 → 768` 两层全连接夹 ReLU，对每个字独立深加工；注意力管"字与字交流"，前馈管"字自己深想"。
- **`DecoderBlock`**（本项目特色）：**两个注意力块**——第一个带 mask（防偷看、防 pad），第二个不带 mask（让字与字充分交流）。标准 GPT 每层只有一个带 mask 的注意力块，这里拆成两个是为教学演示。
- **`Decoder`**：先嵌入，再合并两个 mask（相加后 `>0` 即遮），再过 6 层 DecoderBlock。
- **`GPT_Model`**：Decoder 输出过 `projection` 得到每个位置对每个字的得分。
  - `forward(input, label)`：训练时把预测与标签展平后算交叉熵损失（`ignore_index=0` 让 `<pad>` 不参与损失）。
  - `forward(input)`：推理时直接返回得分。

### 7.4 生成回答（三种方法）

| 方法 | 位置 | 逻辑 |
|---|---|---|
| `greedy_decoder` | 模型方法 | **贪心**：每次取概率最大的字，拼到句尾再喂回模型，循环直到 `<sep>`；超过 100 字强制结束（防无限循环） |
| `random_decoder` | 模型方法 | **随机采样**（轮盘赌）：取概率最高的 top_n 个字当候选，按得分"抽签"——回答更多样。想启用可切换 `answer()` 里被注释的那一行 |
| `answer` | 模型方法 | 对外接口：用户句子 → 字转 id（`\t` 转成 `<sep>` 表示提问结束）→ 调 greedy_decoder → 把两个 `<sep>` 之间的内容取出来当回答 |

**`answer()` 提取回答的原理**：完整输出形如 `[提问..., <sep>, 回答..., <sep>]`，取"倒数第二个 `<sep>` 之后、最后一个 `<sep>` 之前"的部分就是回答。例如 `[你,好,<sep>,我,很,好,<sep>]` → 回答 `"我很好"`。

### 7.5 主程序 `__main__` 流程

```text
1. read_data 读取 30 段对话
2. 读词表，构建 字→id / id→字 映射，得到 vocab_size=7548
3. 设置超参数（max_pos=300, d_model=768, n_layers=6, n_heads=8, ...）
4. 构建数据集 + DataLoader（collate_fn=padding_batch）
5. 创建 GPT_Model，Adam 优化器（学习率 1e-4）
6. 训练循环（10 轮）：
      前向算损失 → loss.backward() 反传 → 梯度裁剪(CLIP=1) → optimizer.step() 更新 → zero_grad() 清梯度
7. （可选）torch.save 保存权重 —— 默认被注释
8. model.eval() → while True: input() → model.answer() → 打印回答
```

### 7.6 张量形状流转表（batch=1，句长 L）

| 阶段 | 形状 | 说明 |
|---|---|---|
| decoder_input | `[1, L]` | 一段对话的 id 序列（补齐后） |
| 嵌入输出 | `[1, L, 768]` | 词向量 + 位置向量 |
| Q / K / V | `[1, 8, L, 64]` | 拆成 8 个头 |
| 注意力得分 / 权重 | `[1, 8, L, L]` | 字与字两两之间的注意力 |
| 加权结果 context | `[1, 8, L, 64]` → 拼回 `[1, L, 768]` | 融合上下文后的新表示 |
| 每层输出 | `[1, L, 768]` | 残差连接保证形状始终不变 |
| projection 输出 | `[1, L, 7548]` | 每个位置对每个字的得分 |
| loss | 标量 | 预测与标签的交叉熵 |

## 八、代码逻辑详解：predict.py

整体流程：**设置超参数 → 读词表 → 创建模型并加载 `model.pt` → `model.eval()` → 对话循环**。模型部分与 `手写gpt.py` 思路相同，差异如下：

| 差异点 | 手写gpt.py | predict.py |
|---|---|---|
| 一层 Decoder 的结构 | `DecoderBlock`：**两个**注意力块 + 前馈 | `DecoderLayer`：**一个**注意力块 + 前馈（更接近标准 GPT） |
| 注意力实现 | 计算直接写在 `MultiHeadAttention.forward` 里 | 单独拆出 `ScaledDotProductAttention` 类（单头零件），再由多头组合 |
| 嵌入层 | 独立的 `EmbeddingLayer` 类 | 直接写在 `Decoder` 里 |
| 损失函数 | 内置 `CrossEntropyLoss` | 无（推理不需要） |
| device | 在 `__main__` 里定义 | 在文件顶部定义（全局可用） |
| 入口 | 训练 + 对话 | 只加载权重 + 对话 |

**加载权重的关键代码**：

```python
model = GPT().to(device)
model.load_state_dict(torch.load('model.pt'))
```

> 超参数必须与训练 `model.pt` 时**完全一致**（词表 7548、d_model 768、max_pos 300、d_ff 2048、d_k=d_v=64、n_heads=8、n_layers=6），否则权重形状对不上，加载直接报错。

## 九、两个文件的关系与常见坑

```text
              ┌── 训练（手写gpt.py）──> 保存权重（torch.save，默认注释掉）
data/ 语料 ───┤
              └── 推理（predict.py）<── 加载权重 model.pt（要求结构与训练时一致）
```

新手最容易踩的 4 个坑：

1. **权重文件不在仓库里**：`.gitignore` 排除了 `*.pt`。想用 `predict.py` 必须自己先训练并保存出 `model.pt`。

2. **保存文件名不一致**：`手写gpt.py` 里保存语句写的是 `model1.pt`（且默认注释），而 `predict.py` 加载的是 `model.pt`。想配套使用，保存时把文件名改成 `model.pt`。

3. **两个文件模型结构不兼容（最重要）**：
   - `手写gpt.py`：每层 = 双注意力（`attention_block1` + `attention_block2`）+ 前馈；
   - `predict.py`：每层 = 单注意力（`dec_self_attn`）+ 前馈。
   - 权重是按"结构+名字"存的，两边的参数名和数量都对不上，所以**一边训练的 .pt 无法被另一边加载**（会报 `size mismatch` / `Missing key(s)`）。
   - 想真正跑通 `predict.py`：需要**按 predict.py 的结构**写一段训练代码训练出 `model.pt`（可参照 `手写gpt.py` 的训练循环，把模型类换成 `predict.py` 里的 `GPT`，并给它加上损失函数）。

4. **超参数必须一致**：加载权重时，模型的每个超参数都必须和训练时一模一样，改任何一个维度都会加载失败。

其他小提醒：

- 对话输入**超过 200 字**时，代码只保留第一个 `\t` 之后的内容（防止超出位置嵌入 300 的上限）。
- 生成回答有 **100 字的强制上限**，防止模型停不下来。
- `answer()` 默认用贪心解码；想要回答更多样，可切换到 `random_decoder(dec_input, top_n=3)`。

## 十、整体流程图

### 训练阶段

```text
data/train.txt
     │ read_data()：按空行切段
     ▼
对话列表 ──MyDataSet──> 样本对（输入=去尾，标签=右移一位）
     │
     │ padding_batch()：补 <pad> 对齐
     ▼
[batch, max_len] 张量 ──> GPT_Model
                          │ 词嵌入+位置嵌入 [b, L, 768]
                          │ 6 × DecoderBlock（注意力+前馈）
                          │ Linear -> 得分 [b, L, 7548]
                          │ CrossEntropyLoss(ignore_index=0)
                          ▼
                        loss ──> loss.backward()
                                梯度裁剪(CLIP=1)
                                optimizer.step() 更新参数
                          （循环 10 轮）
```

### 对话阶段

```text
input("请输入:")
```

## 十一、超参数速查表

| 参数 | 默认值 | 含义 | 调整建议 |
|---|---|---|---|
| `max_pos` | 300 | 位置嵌入表长度（支持的最大句长） | 长对话需调大，但显存占用增加 |
| `d_model` | 768 | 每个字的向量维度 | 越大能力越强、越难训练；与 GPT-2 small 相同 |
| `d_ff` | 2048 | 前馈层中间维度 | 一般取 d_model 的 2~4 倍 |
| `d_k = d_v` | 64 | 每个头的 Q/K/V 维度 | 必须满足 d_k × n_heads = d_model |
| `n_layers` | 6 | Decoder 层数 | 越深越强、越难训、越慢 |
| `n_heads` | 8 | 注意力头数 | 一般取 8/16 |
| `CLIP` | 1 | 梯度裁剪上限 | 防止梯度爆炸 |
| `batch_size` | 1 | 每批样本数 | GPU 上可加大加速训练 |
| `epochs` | 10 | 训练轮数 | 数据多时可减少，欠拟合时增加 |
| 学习率 | 1e-4 | Adam 优化器 | 太大训练不稳定，太小收敛慢 |
| `read_data(..., 30)` | 30 | 只取前 30 段对话 | 删掉 30 即用全量语料 |

## 十二、常见问题 FAQ

**Q1：`ModuleNotFoundError: No module named 'torch'`**
缺少依赖。执行 `pip install torch numpy tqdm`。

**Q2：运行 `predict.py` 报 `FileNotFoundError: model.pt`**
仓库里没有权重文件（`.gitignore` 排除了 `*.pt`），需要先训练并保存，或从别处获得 `model.pt` 放到项目根目录。

**Q3：加载权重报 `size mismatch` 或 `Missing key(s) in state_dict`**
模型结构和训练时不一致。两个可能：① 超参数改过；② 用 `手写gpt.py`（双注意力结构）训练的权重给 `predict.py`（单注意力结构）加载——见第九节第 3 条。

**Q4：训练太慢？**
默认 `batch_size=1` 且可能跑在 CPU 上。改善方法：① 使用 GPU；② 增大 batch_size；③ 保持只用 30 段对话先验证流程。

**Q5：模型的回答不通顺 / 胡言乱语？**
正常现象。默认只用 30 段对话训练，模型只学会了"对话的格式"（先提问、`<sep>` 后接回答），学不会真正的语义。想效果更好：用全量数据 + 更多轮数 + GPU 训练。

**Q6：怎么保存训练好的模型？**
取消 `手写gpt.py` 中 `torch.save(model.state_dict(), r'model1.pt')` 的注释（建议同时把文件名改成 `model.pt`）。

**Q7：怎么退出对话模式？**
终端按 `Ctrl + C`。

**Q8：`Train Loss` 是什么？**
预测"下一个字"和真实标签之间的交叉熵。数字持续下降说明模型在进步；稳定不变可能训练轮数不够或学习率不合适。

## 十三、建议学习路径

1. **跑通**：先 `python 手写gpt.py` 用 30 段对话快速训练一次，输入几句话感受效果；
2. **读数据流**：弄懂 `read_data → MyDataSet.__getitem__ → padding_batch` 这条数据加工链（重点理解"右移一位"）；
3. **读两个 mask**：拿纸画出 pad mask 和上三角 mask 的矩阵，理解"遮住"的含义；
4. **读模型**：按 `MultiHeadAttention → FeedForward → DecoderBlock → Decoder → GPT_Model` 从零件到整体读，对照形状流转表；
5. **读解码**：重点理解 `greedy_decoder` 的"预测一个字 → 拼回句尾 → 再预测"循环，以及 `answer()` 如何用两个 `<sep>` 切出回答；
6. **动手实验**（改代码加深理解）：
   - 把 `epochs` 改成 50，看 loss 和回答质量的变化；
   - 在 `answer()` 里切换 `random_decoder(dec_input, top_n=3)`，对比贪心解码；
   - 用全量数据训练（去掉 `30`），感受数据量的作用；
   - 把 `n_layers` 减到 2，看小模型的表现差别。

> 学完这个项目，你就理解了 GPT 的三大件：**自回归训练、Transformer Decoder、自回归生成**。真正的 ChatGPT 只是把"字"换成"词片"、把模型放大几个数量级、再用更多数据训练而已，核心思想完全一致。
